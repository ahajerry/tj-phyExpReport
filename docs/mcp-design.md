# MCP server 接入方案（未实现）

核对日期：2026-11-10。本文是设计建议，不新增端点、依赖或认证行为。

## 目标与架构

让支持 MCP 的 AI 客户端发现实验字段、校验读数、提交报告、查询任务并取得 PDF。网站不必内嵌模型，也不必把计算逻辑搬进 AI。

建议在现有 Go 服务中增加 `/mcp`，使用官方 Go SDK 的 Streamable HTTP 支持；协议版本与目标客户端联调后锁定，不依赖草案特性。复用实验计算和存储服务，HTTP 与 MCP 共用校验、身份授权、额度和提交逻辑。当前模块是 `experiments`、`httpapi`、`storage`、`render`；如用例编排仍耦合 HTTP，应先提取共享应用服务，避免复制实现。

不建议另起一个同时打开生产数据目录的进程：当前存储有单实例锁和单 worker。若采用独立 MCP 网关，必须通过受保护的后端 API 调用，不能直接访问 SQLite。stdio 适合本地客户端启动进程，网站远程接入优先 HTTP。

## 建议首版工具

| 工具 | 能力 | 当前基础 / 新增工作 |
| --- | --- | --- |
| `list_experiments` | 返回八种实验、说明 | 整理现有实验目录 |
| `get_experiment_schema` | 字段、单位、数量、样例 | 从现有规则维护可发现 schema |
| `validate_report` | 校验并返回计算预览，不创建任务 | 复用 Go 领域计算；新增对外用例 |
| `create_report` | 创建任务，立即返回 job ID | 复用 jobs 提交、额度和队列 |
| `get_report_status` | 返回状态、阶段及错误 | 复用现有任务查询 |
| `get_report_download` | 返回有授权的下载方式 | 补齐非 Cookie 客户端交付 |

字段说明也可作为 resources 暴露；首版不用同时实现大量重复接口。输入 schema 强调读数用字符串，保留有效位数；不让模型自行推断缺失读数。计算错误返回可纠正的字段信息，不泄漏内部路径或编译日志中的个人信息。

PDF 生成继续异步：创建 → 查询 → 下载，不让一次工具调用阻塞到编译结束。协议会话不是报告任务，连接断开不应丢失已提交任务。新增按主体和请求键约束的幂等提交，避免客户端重试重复消耗额度；这不是当前已有能力。

## 身份与文件是主要难点

现有 `report_user` 是匿名浏览器 Cookie，不是 OAuth 账号。外部 MCP 客户端不会自动拥有浏览器 Cookie；不能共享一个全局 Cookie，也不能将展示的八位 userId 当凭证。

私人试用可先使用可撤销、服务端保存摘要的 API token，并绑定独立主体，但须确认目标客户端支持自定义 Bearer 凭证。面向公共客户端建议采用 MCP HTTP 授权规范对应的 OAuth 流程、资源元数据发现、受众校验及权限范围，例如 `reports:read`、`reports:create`。这是新增身份体系，不能假设仓库已经支持。

网站匿名使用保持兼容；如需要查看原浏览器历史，设计用户在网站主动授权的身份绑定流程。每次工具调用和下载都检查主体、任务归属和 scope；MCP 连接或 session ID 不能替代认证。按主体限额并补充 IP/并发限制，现有匿名每日额度本身不能防止滥用。

现有 PDF URL 依赖 Cookie，不能原样返回后期待任意客户端下载成功。可提供受 Bearer 保护的下载端点；客户端不支持时考虑短时、单任务签名链接，明确有效期并避免日志泄漏。不要默认把整份 PDF 编成大段 base64 放进模型上下文。

第一版只支持结构化 JSON，减少附件复杂度。后续通过受控上传端点返回归属明确的 file ID，复用当前大小、格式、解压和像素限制。不要开放任意本地文件路径或任意 URL 抓取，避免文件泄漏与 SSRF。

## 推进顺序与验收

1. 确定首批客户端及私人/公开使用范围，验证所选 SDK、传输和授权兼容性。
2. 提取共享应用用例；先提供实验发现、schema 和校验。
3. 完成主体、授权、幂等提交及异步任务工具，再接入下载。
4. 按需求增加表格与图片上传，最后考虑 prompts 等辅助功能。

部署沿用 HTTPS 反向代理，增加 `/mcp` 路由；按 SDK 传输模式配置超时和流式响应，检查 Origin（存在时）、请求大小与速率。公网开放前验证未授权拒绝、跨主体查询/下载拒绝、重复提交、额度一致性、断线与重启恢复、八种实验数值一致性及至少一个真实客户端完整生成下载。后端与并发修改分别运行仓库规定的 backend、race 和容器验收。

MCP 和 Typst 可以独立推进。前者增加调用入口，后者替换 PDF 排版实现；建议分开交付，便于定位回归。

参考：[官方 Go SDK](https://github.com/modelcontextprotocol/go-sdk)、[MCP HTTP 授权规范（2025-11-25 版本）](https://modelcontextprotocol.io/specification/2025-11-25/basic/authorization)。实施时锁定支持的协议版本与 SDK 版本，并按该版本规范验收。
