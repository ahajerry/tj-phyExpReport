# 0003：PDF 与源码输入快照同时发布

状态：已接受，2026-10-31。

背景：单独 `.typ` 无法携带图片、共享模块和数据；下载时按最新模板重建会造成源码与既有 PDF 不对应。

决定：每次渲染同时生成 PDF 与 ZIP，ZIP 保存实际编译输入；二者落盘后任务才变为 done。两个下载接口采用相同匿名归属校验，只读取归档。前端在 PDF 按钮旁增加 Secondary Button 下载 ZIP。

选择理由：ZIP 保持可编译的相对目录结构，又无需把图片编码进单个源码文件。快照使模板升级后已有报告仍有对应源码，且下载不消耗生成额度。

影响：磁盘同时保存两种产物及原图；备份需包含整个数据目录。文件系统与 SQLite 没有跨介质事务，通过状态门控避免发布半成品，崩溃后可重编译。字体不打包，编辑读数不会自动重算物理结果。文件结构与重现边界见 [报告契约](../specs/reports.md)。
