# 0001：Go、SQLite 与单 worker

状态：已接受；2026-10-31 追认仓库已有实现，不代表原始决策发生于该日。

背景：生产已经从 Python 迁到 Go，计算、导入、HTTP 和持久化有明确模块边界；现有部署按一个实例运行。

决定：继续由 Go 承担唯一后端及物理计算，以 SQLite 持久化队列，一个 worker 串行编译，数据目录排他锁防止并发实例。此次更换报告引擎不重写计算层。

理由：保持已有数值参考与部署模型，避免引入任务服务、跨语言运行时或重复公式实现。

影响：可以恢复未完成任务，但不承诺只编译一次；同一数据卷不能水平扩容。多实例、账号或严格反滥用需求应另立决策。现行规则见 [架构](../specs/architecture.md)。
