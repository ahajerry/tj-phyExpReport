## 结论

**Go 重写可行，建议采用渐进替换，保留 React、SQLite 和 XeLaTeX，前端统一使用 pnpm。** 先固定行为和修复验证基线，再由 Go 接管 HTTP、持久化和任务调度，随后按实验迁移计算、导入和模板填充。Python 可作为过渡期的受控子进程，最终是否完全移除取决于 HEIC/AVIF 图片兼容验证结果。

主要收益是明确模块边界、类型约束、可测试性和部署可控性。PDF 的主要工作仍由外部 XeLaTeX 执行，不能据语言选择承诺编译提速，也不能把最终部署描述成“只需要一个 Go 二进制”。

本次检查：lint、前端构建及三个数据相关脚本通过；Python 67 项测试中 61 项通过、6 项跳过；模板检查与页面样例检查各发现一处现存失败。环境缺少 XeLaTeX，PDF 编译、页数与视觉效果未验证。详细命令和限制见 [04](04-development-and-validation.md)。
