# 05 Go 后端重写可行性评估

## 判断与适用目标

**技术可行，工程上建议渐进替换。** 当前领域计算规模有限，不依赖 NumPy/SciPy 或大型 Python 专属框架；HTTP、SQLite、文件与子进程编排均可迁到 Go。难点是保留已有实验语义和附件行为，而非选择 Web 框架。

如果目标只是更快生成 PDF，尚不足以支持全面重写：当前每个任务两次 XeLaTeX 才是需要实测的耗时环节。如果目标是长期维护、严格接口、部署和故障恢复可控，Go 具有合理价值。先测量再决定 worker 并发数，不能把 goroutine 数量直接当作编译容量。

## 方案比较

| 方案 | 优点 | 代价 | 建议 |
| --- | --- | --- | --- |
| 整理 Python 模块，继续维护 | 行为漂移最小，可快速修复当前问题 | 不满足 Go 技术栈目标 | 可作为低成本基线方案 |
| 一次性用 Go 全部重写 | 最终形态直接 | 同时承担公式、文件、队列、版式风险，难定位回归 | 不作为首选 |
| Go 服务 + Python 过渡渲染器，逐模块迁移 | HTTP/队列收益先交付，保留可对照实现 | 过渡期有双语言协议与部署成本 | **推荐** |

“过渡渲染器”是计划新增的边界，仓库当前没有独立 worker RPC/CLI 协议。必须先抽出纯验证、导入、渲染入口，才能接入 Go；不能只把 Python HTTP 服务藏在后面且继续共享写队列。

## 能力映射

| 当前能力 | Go 候选 | 评估 |
| --- | --- | --- |
| HTTP / Cookie / 上传 | 标准库 `net/http`、`mime/multipart` | 路由数量少，优先标准库；配置 body 上限、服务器超时与 graceful shutdown。[官方文档](https://pkg.go.dev/net/http) |
| SQLite | `database/sql` + `modernc.org/sqlite` | 候选驱动不依赖 CGo；需要验证目标平台、锁与事务语义，不能把更换驱动等同于队列并发已安全。[驱动文档](https://pkg.go.dev/modernc.org/sqlite) |
| Decimal 运算与修约 | `cockroachdb/apd/v3` 候选 | 有上下文、舍入和高精度运算接口；需逐式验证与 Python Decimal 的一致性。[库文档](https://pkg.go.dev/github.com/cockroachdb/apd/v3) |
| CSV | `encoding/csv`，GB18030 另接编码适配 | 保留 BOM、空行、固定四行分组和列顺序 |
| XLSX | Excelize 候选 | 可读取工作簿；配置 ZIP 解压资源限制，验证公式缓存和原始值读取，不能用格式化显示值代替数字。[作者文档](https://xuri.me/excelize/en/workbook.html) |
| JPEG/PNG/GIF | 标准库 image 体系 | 能处理基本格式，但 EXIF 方向与缩放仍需明确实现。[官方文档](https://pkg.go.dev/image) |
| TIFF/WebP/HEIC/AVIF | 附加解码器或受控转换程序 | 不属于标准 image 包自动保证的能力；HEIC/AVIF 是完全移除 Python 的主要验证项 |
| TeX 编译 | `os/exec` + context | 直接执行固定程序和参数，不经 shell；设置 cwd、超时、进程终止和日志上限。[官方文档](https://pkg.go.dev/os/exec) |
| 模板填充 | 自有小型填充器，或显式模板适配器 | 保留 LaTeX 转义和图点校验，不将 HTML 自动转义套用到 TeX |

以上是候选设计，没有安装依赖或锁定版本。正式选型需要在目标系统验证许可证、平台支持和行为；不因为库可用就承诺无 C 依赖的全格式图片支持。

## 数值迁移策略

1. 输入使用 decimal string，禁止先反序列化成 float64 再转十进制。新客户端输出字符串；兼容 JSON 数字时使用保留原数字文本的解码方式。
2. 保留 `rawText`、解析值、单位、显示值四个层次。单位转换集中到领域模块，前端只是输入提示。
3. 以当前 Python 默认 Decimal 上下文为起点，明确精度、舍入、溢出与非法值处理；特别覆盖 sqrt、1.5 次幂与 division。Go 库函数名称相似不保证逐步舍入相同。
4. 末端修约单独建包，跨 Python/TypeScript/Go 共享输入与预期字符串样本。`2.95` 等临界值必须一次取舍，不能先 round 再 format。
5. π 常量、float 转换的 log/atan2 边界先按旧实现定义；超越函数的中间值使用经样本确认的绝对/相对误差阈值，最终成品字段原则上逐字符串一致。
6. 数值修正若改变物理结论，应作为带 calculationVersion 的独立变更，有说明和新样本；不能以“重构”名义顺带修公式。

跨语言基准不能只比较“都生成了 PDF”。至少比较归一化后的输入、关键未修约中间值、最终数值字符串、图点和填充后的文本字段。对已知旧 bug 设明确的差异清单，不把所有旧行为都永久视为正确。

## 图片与 PDF 决策

初期复用 Pillow/pillow-heif，以保持方向、尺寸、图片格式和最终 PDF。后续独立评估图像后端；不能默默删除 HEIC/AVIF，也不能把“浏览器先转 JPEG”作为覆盖所有 API 客户端的替代方案。

Go + 原生图像组件或外部转换器也可能继续需要系统库。建议把图片处理隔离成接口，在真实手机图片、透明图片、损坏图片、超像素图和多帧图样本上确定后端。若全部满足再去掉 Python，否则明确保留小型图像 worker；这不会妨碍 HTTP、队列和计算主体使用 Go。

LaTeX 第一轮继续保留。替换为 Go PDF 绘图库或 HTML 打印会额外引入公式、中文字体、分页、图形和装订线差异，应单独立项。

## 先做的四项技术验证

| 验证 | 范围 | 通过标准 | 失败时处理 |
| --- | --- | --- | --- |
| 数值 | 末端修约 + 示波器 + 油滴非整数幂 | 基准字段一致；临界样本无未解释差异 | 调整 Decimal 方案，继续 Python 计算 |
| 表格 | 三类仪器导入和新旧单位转换 | 同样文件返回同样可编辑值，错误类型可预期 | 保留 Python importer，补齐 fixtures |
| 任务 | 临时旧库副本、额度、崩溃恢复、文件归档 | 不丢任务、不越权、不重复计额度 | Go 不接生产写入 |
| 版式/图像 | 八种真实编译，图片格式矩阵 | 数值/图点/页数符合基线，关键页视觉通过 | 保留旧 renderer/图像处理 |

## 投入与边界

以一名熟悉 Go/React 且能获得实验领域复核的开发者估算：现状基线与 pnpm 2–4 人日，过渡协议及 Go HTTP/队列 5–8 人日，计算与导入 8–15 人日，模板/图片/发布验证 5–10 人日，前端拆分 4–7 人日，总约 **24–44 人日**。这是基于代码范围的规划估算，不是交付承诺；不含重新设计全部 UI、账号系统、多租户或重新制作全部报告模板。

Go 无硬性技术阻断；尚未闭合的是环境、样例和行为一致性验证。路线图中的退出条件应优先于日历日期。
